## 三、跌倒判断参数（核心 ⭐）

### 3.1 关键点置信度过滤

| 参数 | 默认值 | 代码位置 | 说明 |
|:-----|:------|:---------|:-----|
| `min_kp_conf` | **0.3** | `fall_detect.py:26` | 关键点置信度低于此值的丢弃，不参与计算 |

> 每个关键点有单独的 `confidence` 字段（0~1）。低于 0.3 的关键点可能是遮挡或误检，不应该用来判断跌倒。

### 3.2 肩髋垂直距离阈值（主判断逻辑）

| 参数 | 默认值 | 代码位置 | 说明 |
|:-----|:------|:---------|:-----|
| `threshold` | **0.2** | `fall_detect.py:25` | 原始参数（0~1 归一化值） |
| 实际距离阈值 | **`threshold × 200 = 40 像素`** | `fall_detect.py:146` | 在 640×640 图像上，肩-髋垂直距离 < 40px = 疑似跌倒 |

**为什么是 40 像素？**
- 640×640 图像上，站立时肩髋垂直距离约 100~180px
- 坐下时约 40~60px
- 躺下/跌倒时约 10~40px
- `0.2 × 200 = 40` 是实战标定值，平衡了坐姿和跌倒

**香橙派上实现：**
```python
vertical_distance = abs(avg_hip_y - avg_shoulder_y)  # 像素值
fall = vertical_distance < 40  # 直接比较像素值
```

### 3.3 身体角度阈值（辅助判断）

| 参数 | 默认值 | 代码位置 | 说明 |
|:-----|:------|:---------|:-----|
| `use_angle` | **true** | `fall_detect.py:27` | 是否启用角度辅助判断 |
| `angle_threshold` | **60.0°** | `fall_detect.py:28` | 身体倾斜角 > 60° = 疑似跌倒 |

**角度计算方式：**
```
肩部中点 (x1, y1)
髋部中点 (x2, y2)
dx = x1 - x2
dy = y1 - y2
angle = atan2(|dx|, |dy|)    # 垂直站立时 angle≈0°，水平躺下时 angle≈90°
跌倒 = angle > 60°
```

**为什么是 60°？**
- 正常站立：5°~15°
- 弯腰捡东西：30°~50°
- 坐床沿：40°~55°
- 跌倒躺下：70°~90°
- `60°` 作为阈值能区分"弯腰"和"跌倒"

### 3.4 跌倒综合判断

```python
def is_fall(vertical_distance, body_angle, threshold=40, angle_threshold=60, use_angle=True):
    fall_reason = []
    
    # 条件A：肩髋垂直距离太小（主判断）
    if vertical_distance and vertical_distance < threshold:  # < 40px
        fall_reason.append(f'垂直距离过小: {vertical_distance:.1f} < {threshold}')
    
    # 条件B：身体倾斜角度太大（辅助判断，默认启用）
    if use_angle and body_angle and body_angle > angle_threshold:  # > 60°
        fall_reason.append(f'倾斜角度过大: {body_angle:.1f} > {angle_threshold}')
    
    # 条件A或条件B任一满足 → 判定跌倒
    return len(fall_reason) > 0, fall_reason
```

> **实战结论**：垂直距离法是主力，角度法是辅助。两者 OR 关系，任一满足就报警。

## 四、状态机参数（方案中新增）

| 参数 | 建议值 | 说明 |
|:-----|:------|:------|
| `FALL_PENDING_THRESHOLD` | **3 帧** | NORMAL→PENDING：连续3帧判定为跌倒才进入待确认 |
| `FALL_CONFIRMED_THRESHOLD` | **5 帧** | PENDING→CONFIRMED：再连续5帧判定为跌倒才触发报警 |
| `FALL_RECOVER_THRESHOLD` | **10 帧** | CONFIRMED→NORMAL：连续10帧判定为正常才恢复 |
| `PENDING_CANCEL_THRESHOLD` | **3 帧** | PENDING→NORMAL：连续3帧判定为正常就取消待确认 |

**为什么是这些值？**
- 3帧+5帧=8帧 ≈ 1~2秒（FPS≈5-8），弯腰捡东西一般 < 1秒，可以过滤掉
- 恢复要10帧 ≈ 2秒，防止报警刚触发又取消，反复横跳
- 3帧取消待确认，防止弯腰经过时短暂触发

## 六、GPIO 引脚定义（香橙派5B 40pin）

> **需要你实际接线后确认引脚号**，这里提供建议的引脚分配：

| 外设 | GPIO 编号 | 物理引脚 | 说明 |
|:----|:---------|:--------|:-----|
| 蜂鸣器 | **GPIO84** | Pin 32 | 有源蜂鸣器，高电平响 |
| LED（绿色） | **GPIO85** | Pin 33 | 正常呼吸灯，PWM 控制亮度 |
| LED（红色） | **GPIO86** | Pin 35 | 报警灯，报警时亮 |
| PIR 传感器 | **GPIO87** | Pin 36 | 输入模式，检测有人/无人 |

> 引脚映射以 `/sys/class/gpio` 为准，不同系统版本可能有差异。
> Orange Pi 5B GPIO 编号 = 物理引脚对应的 SoC GPIO 号（非 wiringPi 编号）。

### GPIO 控制逻辑

```python
# 正常状态
LED_绿 = 呼吸灯效果（PWM 慢闪，周期 2 秒）
LED_红 = 灭
蜂鸣器 = 静音

# 跌倒报警（CONFIRMED 触发）
LED_绿 = 灭
LED_红 = 快速闪烁（周期 0.2 秒）
蜂鸣器 = 持续响（或间歇响，周期 0.5 秒）

# 报警解除（人工确认或恢复后）
LED_绿 = 呼吸灯
LED_红 = 灭
蜂鸣器 = 静音
```

## 八、MQTT 上报参数

| 参数 | 建议值 | 说明 |
|:-----|:------|:------|
| Broker 地址 | `192.168.x.x` | 你的 PC 或 MQTT 服务器 IP |
| Broker 端口 | **1883** | MQTT 标准端口（非加密） |
| Client ID | `orangepi5b_fall_001` | 设备唯一标识 |
| 心跳间隔 | **30 秒** | 发 `fall/heartbeat` |
| QoS | **1** | 至少一次投递 |

### MQTT 主题设计

| 主题 | 方向 | JSON 载荷 | 触发条件 |
|:-----|:-----|:----------|:---------|
| `fall/alert` | 香橙派→云端 | `{"device":"orangepi5b","room":"301","timestamp":xxx,"status":"fall"}` | 跌倒确认 |
| `fall/heartbeat` | 香橙派→云端 | `{"device":"orangepi5b","timestamp":xxx,"fps":5.2,"status":"normal"}` | 每 30 秒 |
| `fall/ack` | 云端→香橙派 | `{"device":"server","command":"reset","timestamp":xxx}` | 报警确认/解除 |

### MQTT 断线处理

```python
断线后：
  1. 每 5 秒自动重连
  2. 重试期间跌倒事件缓存在本地队列
  3. 重连成功后补发未发送的报警
  4. 连续 5 次重连失败 → OLED 显示 "MQTT Disconnected"
```
