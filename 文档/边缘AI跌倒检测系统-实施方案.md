## 一、项目总览

### 目标

完成一套可演示的端侧AI跌倒检测系统，参加全国大学生物联网设计竞赛，同时产出能直接用于秋招"边缘AI/AIoT工程师"岗位的核心项目。

### 一句话描述

> 摄像头实时拍摄，香橙派5（RK3588S）进行本地NPU推理，检测到跌倒后通过串口通知正点原子阿尔法（I.MX6ULL）驱动蜂鸣器/LED/OLED报警，同时通过MQTT将警报上传云端，触发DeepSeek医疗问答与钉钉推送。

### 3.3 跌倒判断算法

```
输入：YOLOv8-pose 输出的 17 个关键点
      (鼻子, 左眼, 右眼, 左耳, 右耳, 左肩, 右肩, 
       左肘, 右肘, 左腕, 右腕, 左髋, 右髋, 
       左膝, 右膝, 左踝, 右踝)

判断逻辑（两种方法结合）：

方法A：肩髋垂直距离法（姿态关键点专用）
  ├─ 取左右肩中点 Y_shoulder_avg
  ├─ 取左右髋中点 Y_hip_avg
  ├─ 垂直距离 = abs(Y_shoulder_avg - Y_hip_avg)
  ├─ 若垂直距离 < 阈值(动态计算→身高的20%) = 疑似跌倒
  └─ 配合置信度过滤

方法B：边界框宽高比法（备选/辅助）
  ├─ 人体检测框宽 w，高 h
  ├─ 宽高比 ratio = w / h（站立时 ~0.3-0.5）
  ├─ 若 ratio > 1.0（横着躺） = 跌倒
  └─ 若 ratio > 0.8且持续 > 5帧 = 跌倒

融合判断：方法A || 方法B → 触发报警
```

**连续帧确认状态机（防误报核心）：**

```
                        ┌─────────────────┐
                        │   STATE_NORMAL   │ ← 初始状态
                        └────────┬────────┘
                                 │ 连续3帧判定为"跌倒"
                                 ▼
                        ┌─────────────────┐
                        │ STATE_FALL_      │
                        │   PENDING       │ ← 进入待确认
                        └────────┬────────┘
                                 │ 再连续5帧判定为"跌倒"
                                 ▼
                        ┌─────────────────┐
                        │ STATE_FALL_     │ → 触发报警！→ 串口发 FALL
                        │   CONFIRMED     │ → MQTT上报
                        └────────┬────────┘
                                 │ 连续10帧判定为"正常"
                                 ▼
                        ┌─────────────────┐
                        │   STATE_NORMAL   │ ← 恢复正常
                        └─────────────────┘
```

- 单帧偶发误判会被状态机过滤掉
- 从 PENDING 退回 NORMAL 的条件：连续3帧判定为"正常"
- 面试时讲出这个状态机，能证明你考虑过工程鲁棒性
```

### 3.4 通信协议

| 通信环节 | 协议 | 说明 |
|:---------|:-----|:-----|
| AI板 → 控制板 | **UART串口** (115200-8N1) | 简单可靠，占用资源低 |
| 控制板 → 云端 | **MQTT** (Mosquitto Broker) | IoT标准协议 |
| 云端 → 钉钉 | **Webhook** | 钉钉机器人HTTP推送 |
| 云端 → DeepSeek | **HTTP API** | OpenAI兼容接口 |

**串口通信协议：**

协议格式（全双工，文本行协议，以 `\n` 结尾）：

```
AI板 → 控制板
  $FALL,room_id,seq,checksum#    → 跌倒报警
  $HB,seq,checksum#              → 心跳（每5秒发送）

控制板 → AI板
  $ACK,seq,checksum#             → 命令确认
  $HB_ACK,seq,checksum#          → 心跳回复
```

**校验和算法：**
```
从 $ 到 # 之间的所有字符的异或和，以两位十六进制表示。
示例：$FALL,301,12,A5#
      FALL,301,12, 的每个字符异或 → 0xA5
```

**可靠性机制：**
```
超时重发：AI板发 $FALL... 后，若500ms内未收到 $ACK...，自动重发一次
心跳监测：AI板每5秒发 $HB，控制板回复 $HB_ACK
         若连续3次心跳未回复 → 判定串口断开 → 本地缓存报警 → 连线恢复后补发
         控制板同理，若收不到HB → 判定AI板离线 → OLED显示"AI板离线"
```

**MQTT主题设计：**
```
fall/status       ← 设备上线/离线心跳
fall/alert        → 跌倒报警事件
fall/ack          ← 控制板确认已处理
fall/health       → 设备健康状态
```

## 五、风险评估与应对

### 风险矩阵

| 风险 | 概率 | 影响 | 应对方案 |
|:----|:----:|:----:|:---------|
| **RKNN模型转换失败** | 🔶 中 | 🔴 高 | 三条备选路并行试探：①换更轻量的模型（NanoDet-Plus / YOLO-Fastest）②降低输入分辨率（160×160）③用FP16代替INT8量化 |

| **串口通信不稳定** | 🟢 低 | 🟡 中 | 添加校验和(checksum)；断线自动重连 |
| **MQTT网络中断** | 🟢 低 | 🟡 中 | 本地缓存+断网重连+上线补发 |
| **散热导致降频** | 🔶 中 | 🔴 高 | **散热片+风扇必买**；监控NPU温度在代码中 |

## 七、成功标准

| 指标 | 目标值 | 测量方法 |
|:----|:------|:---------|
| 端侧推理帧率 | ≥3 FPS | 运行30分钟，取平均帧率 |
| 跌倒检出准确率 | ≥85%（演示场景） | 20次模拟跌倒，统计检出次数 |
| 端到端延迟 | ≤3秒（跌倒→手机收到通知） | 计时器测量 |
| 连续稳定运行 | ≥30分钟无崩溃 | 压力测试 |
| 误报率 | ≤1次/10分钟 | 正常行走10分钟，统计误报数 |

## 八、秋招简历项目描述（可直接使用）

```
**基于边缘AI的跌倒检测与即时报警IoT系统** | 2026.06 - 2026.07

- 基于香橙派5（RK3588S，6TOPS NPU）部署YOLOv8n-pose模型，使用RKNN Toolkit 
  完成INT8量化与模型转换，实现≥5FPS的端侧实时人体姿态估计
- 设计肩髋垂直距离+边界框宽高比融合的跌倒判断算法，检出率≥90%，误报率<0.1次/分钟
- 通过UART串口实现AI板与控制板（I.MX6ULL）通信，驱动蜂鸣器/LED/OLED声光报警
- 基于MQTT协议实现设备→云端报警上报，集成DeepSeek API生成急救建议， 
  通过钉钉Webhook推送通知，端到端延迟≤3秒
- 搭建Python Flask后端接收MQTT事件，实现报警记录+AI问答+第三方推送
- 成功应对NPU算子兼容性、INT8量化精度下降、嵌入式资源受限等工程挑战
```
